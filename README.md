# Kavita on Railway

[Kavita](https://github.com/Kareadita/Kavita) is a self-hosted digital library and
reading server for ebooks, comics and manga. This repository is the upstream image
plus one entrypoint — it adds nothing to the application and forks nothing.

## Why a wrapper is needed

Kavita's `Program.cs` calls `config.Sources.Clear()` before adding
`config/appsettings.json`, so **no environment variable configures the application**.
Three things Railway needs therefore have to happen at boot:

| Need | Why it cannot be a variable |
|---|---|
| Config store on the volume | The config directory is hardcoded to `<cwd>/config`, and a Railway service may mount only one volume — so the volume holds config *and* libraries, and `<cwd>/config` is symlinked into it. |
| A first administrator | The first account registered through `POST /api/Account/register` becomes the admin and the endpoint refuses afterwards. Without this the server is claimable by whoever reaches the URL first. |
| `hostName` server setting | It is a database row, and it is what Kavita substitutes into every generated link. |

Everything the entrypoint does is idempotent: it creates the admin only when none
exists, moves `hostName` only off an empty value, and creates libraries only when
the server has none.

## Variables

None are required — the image boots and serves with all of them unset. Set
`KAVITA_ADMIN_PASSWORD` for an unattended deployment, or the first visitor to the
URL will be able to claim the server.

| Variable | Default | Purpose |
|---|---|---|
| `KAVITA_ADMIN_USERNAME` | `admin` | First administrator's username |
| `KAVITA_ADMIN_PASSWORD` | *(unset)* | First administrator's password, minimum 6 characters. Consumed by the entrypoint and unset before the server starts. |
| `KAVITA_ADMIN_EMAIL` | *(username)* | Optional; Kavita defaults it to the username |
| `KAVITA_HOST_NAME` | `https://$RAILWAY_PUBLIC_DOMAIN` | Public URL used in generated links |
| `KAVITA_DATA_DIR` | `/data` | Volume mount point |
| `KAVITA_MEDIA_DIR` | `/data/media` | Parent of the `books/`, `comics/` and `manga/` libraries |
| `KAVITA_DEMO_MEDIA` | `true` | Seed four public-domain Project Gutenberg books once |
| `KAVITA_BOOTSTRAP` | `true` | Set `false` to skip first-run setup entirely |
| `KAVITA_CACHE_MB` | `75` | Kavita's in-memory cache budget |
| `KAVITA_ALLOW_STAT_COLLECTION` | *(Kavita's own default)* | `false` opts out of anonymous usage stats. Left unset the admin UI toggle wins. |

`KnownProxies` is deliberately never written. Kavita passes each entry to
`IPAddress.Parse`, which rejects a CIDR and would take the process down at startup,
and Railway's edge has no fixed address to list. Nothing is lost by omitting it: the
single `Request.Scheme` read in the codebase is overridden by `hostName`.

## Adding your own books

Kavita has no web upload for library files — they arrive over the filesystem:

```bash
railway volume files --volume <volume> upload ./book.epub /data/media/books/book.epub
```

Each book needs its own folder — `books/<Series>/<file>.epub` — because Kavita's
scanner walks sub-directories only and silently ignores files sitting at a library
root. Then run **Scan library** from the library's ⋮ menu, or wait for the nightly scan.

## Notes

- Port 5000 is fixed: `Configuration.GetPort` returns the default unconditionally
  inside Docker, so `PORT` exists only so Railway probes the right port.
- The JWT signing key is generated by Kavita on first boot and persisted to
  `appsettings.json` on the volume. It is deliberately not a variable.
- EPUBs may contain scripts, which Kavita renders (upstream GHSA-r4qc-3w52-2v84).
  Load books you trust.
